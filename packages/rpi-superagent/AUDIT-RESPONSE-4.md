## 6. 路径优化 3：Dash `Bucket` 能否扩展成任务维度 ✅ 已核实，审计的怀疑成立

**审计的保留**：

> 我没有评估 `pi-dingo-dash` 的 `dingo.rs` 能否扩展出「任务视图」——它说「复用 Dash `Bucket`」，
> 但 Dash 的 Bucket 是**会话**维度，扩展成**任务**维度需要看完整实现

**我读了完整实现，审计的怀疑成立**：

```rust
// crates/core/src/dingo.rs:111
pub struct DingoItem {
    pub session: SessionMeta,      // ← 强绑定会话
    pub bucket: &'static str,
    ...
}

// crates/core/src/dingo.rs:211
fn classify_one(s: &SessionMeta, lv: Option<&LiveView>, ...) -> DingoItem
```

`classify_one` 的整条判定链（`awaiting_ai` / `live_stale` / `looks_interrupted` /
`aborted_after_user`）**全部基于会话文件的状态**（`last_at` / `last_assistant_at` /
`mtime_ms` / `last_stop_reason`）。

**结论**：任务维度**不是简单复用**——需要**新判定链 + 新 item 类型**，
因为 Task 的状态来源（落盘的 Task 记录）与 SessionMeta 完全不同。

**已写进文档**：

- 风险表第 15 条（新增）：「Dash `Bucket` 是会话维度，复用需要新判定链」
- `DESIGN-SUPERAGENT.md` §11 第 10 项：「**注意：`DingoItem` 强绑定 `SessionMeta`，
  `classify_one` 是会话维度的，任务维度需要新判定链，不是简单复用**」

**这一条影响 M1 的工作量**（比原估的 ~500 行略高），但不影响总体量级。
