## 1. 我上一轮的推论错了

上一轮我写：

> 重启后 `running` 的任务**本来就在死**——它的子进程也被杀了（`kill_and_reap` 杀进程树）。
> 所以「接管」在语义上是错的：**任务真的没在跑了**。

**这是错的。** 我当时假设宿主退出时会走 `kill_and_reap`。

**实测**（本轮做的）：

```
$ python3 -c "父进程 setpgid(0,0) 后 fork 子进程；父被 SIGKILL"
父 61591 CHILD 61592
→ 子进程仍然存活（孤儿进程）
```

**根因**（`crates/rpi-plugin-sdk/src/process.rs:60-77`）：

```rust
pub struct ProcessTree(i32);
impl ProcessTree {
    pub fn prepare(command: &mut Command) {
        command.process_group(0);      // ← 只 setpgid，不 setsid
    }
    pub fn kill(&self) {
        unsafe { libc::kill(-self.0, libc::SIGKILL); }
    }
}
```

`process_group(0)` = `setpgid(0,0)`，**不建立新会话**。所以：

1. 宿主被 SIGKILL 时，**没有任何信号**发给子进程
2. 子进程**存活成孤儿**，继续跑它的工作
3. `kill_and_reap` 只在**取消/超时**时调用，宿主崩溃走不到

**而且这个孤儿可能活很久**：`rpi -p` 是 print 模式，**中途不输出**，只在最后写一次 stdout。
所以一个跑 20 分钟的子进程，在宿主崩溃后可能继续跑 20 分钟，没人收结果。

**我上一轮说「`rpi -p` 中途不输出，所以会收到 SIGPIPE 死」——那也不对**：
SIGPIPE 只在它**写**的时候才触发，而它只在结束时才写。

## 2. 修掉的缺陷：孤儿进程泄漏

### 2.1 方案

1. 任务快照记录它启动的子进程 **pid**
2. 读任务时，扫描所有 pid：**还活着且不是本进程的** → 孤儿 → 杀掉

**为什么 pid 要记在任务上**：任务是唯一跨重启存在的东西。它是「谁在替我干活」的登记处。

### 2.2 记录 pid 的三个时机

| 时机 | 记什么 |
|---|---|
| dispatch **开始** | 空（子进程还没起） |
| dispatch **运行中**（心跳，每 60s） | **当前活着的子进程 pid** ← 关键 |
| dispatch **结束** | 本波的子进程 pid |

**心跳带 pid 是关键**：如果只在 dispatch 结束时记，宿主中途崩溃就丢了这个信息——
而那正是最需要它的时候。

### 2.3 三个 macOS 特有的坑（实测踩到并修掉）

**坑 1：zombie 被误判为存活**

`kill -0 <pid>` 对 zombie 返回成功（进程还在进程表里，只是已退出）。
一个**已完成的子进程**会被误判为「还活着」→ 被当成孤儿反复 kill。

实测证据：
```
发 kill 前 ps: 68824 S    python3 cross2.py
发 kill 后 ps: 68824 Z    <defunct>
```
`kill -0` 说它活着，但它已经是 `Z`（zombie）。

**修法**：额外查 `ps -o state=`，`Z` 开头就算已死。

```rust
let state = std::process::Command::new("ps")
    .args(["-o", "state=", "-p", &pid.to_string()])
    .output()
    .map(|out| String::from_utf8_lossy(&out.stdout).trim().to_string())
    .unwrap_or_default();
!state.starts_with('Z')
```

**坑 2：跨进程组 kill 报 EPERM**

我最初用 `kill -KILL -<pgid>` 杀整组。实测：

```
$ /bin/kill -KILL -67461
kill: -67461: Operation not permitted
```

**macOS 不允许非组成员 kill 整个进程组**。而孤儿的进程组**没有活着的成员**——
我们不是它的成员。

**修法**：直接 kill pid（跨会话也有效，实测同用户即可），再递归 kill 它的后代。

```rust
pub(crate) fn kill_process_tree(pid: u32) {
    #[cfg(unix)]
    {
        kill_descendants(pid);          // 先杀后代，否则会被 reparent 藏起来
        let _ = std::process::Command::new("kill").arg("-KILL").arg(pid.to_string()).status();
    }
    ...
}
```

**坑 3：`/bin/kill` 不支持负 pid**

那是 shell builtin 的语法。`/bin/kill -KILL -123` 报 "No such process"（还返回 0，误导）。

## 3. e2e 验证：孤儿真的被清理

```
1) 造真孤儿：父进程退出，子进程在跑
   状态: S（睡眠中，真的在跑）
2) 把它的 pid 写进任务快照
3) 新进程读任务（superagent_task action=list）
4) 结果：孤儿状态 S → Z（已被 kill）
   任务读出来: [~] orph1 working — Long job
```

**孤儿被杀了，任务仍然可读。**

## 4. 现在的语义（修正后）

| 场景 | 实际发生 |
| --- | --- |
| 宿主崩溃，子进程存活 | 子进程成孤儿继续跑 → **下次读任务时被杀** |
| 宿主崩溃，任务状态 | `working` → 超过 30 分钟变 `abandoned`；否则仍是 `working` |
| 宿主正常退出 | `kill_and_reap` 杀进程树 → 无孤儿 |

**所以「接管」现在有了明确的对象**：不是接管一个还活着的任务，而是
**清理一个已经没人管的孤儿，然后把任务标记成 abandoned，让人决定要不要重跑**。

**这正是我上一轮推论的「后半段」是对的、前半段是错的**：
- ✅ 对：标 abandoned、让人决定重跑
- ❌ 错：任务「真的死了」——它没死，它在跑

## 7. 需要第十二轮审计判断的取舍

### 7.1 三个具体取舍

| # | 取舍 | 我的选择 |
| --- | --- | --- |
| 1 | **孤儿清理的触发点** | 读任务时清理。**但如果没人读任务，孤儿就一直跑**——这是个真实的缺口（见 §7.2） |
| 2 | **清理时机 vs 误杀风险** | 直接 kill pid。如果 pid 被系统回收给了别的进程，就会误杀——**理论风险，实践中 pid 复用需要很久** |
| 3 | **pid 要不要记进任务快照**（每次心跳都写，增加快照量） | 要。实测 300 条 append 5ms，量不成问题 |

### 7.2 一个我还没解决的缺口（请重点看）

**孤儿清理依赖「有人读任务」。**

如果宿主崩溃后**没有任何人打开这个会话**，孤儿会一直跑——可能是几小时。

**可能的解法**：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A. 接受 | 「反正没人关心这个会话」 | 孤儿可能长期占用 CPU/内存 |
| B. 启动时清理 | 新 rpi 进程启动时扫所有会话的 task 快照 | 要能枚举会话目录——**可行**（`--session-dir` 就是） |
| C. 子进程自己看门狗 | 子进程定期检查父进程是否活着 | 要改 `rpi -p` 的启动方式，或用 wrapper |

**我倾向 B**（在插件加载时扫一次 session 目录），但那需要读别的会话的文件——
**越界了**（插件不该乱读用户的会话目录）。

**请第十二轮审计判断**：这个缺口值得做吗？如果做，B 的越界问题怎么解？

### 7.3 需要复核的实现判断

| # | 判断 | 依据 |
| --- | --- | --- |
| 1 | **zombie 算已死** | `kill -0` 说它活着但 `ps` 说 `Z`——它是已完成的子进程，不是孤儿 |
| 2 | **直接 kill pid 而非 kill -pgid** | 跨组 kill 报 EPERM；直接 kill pid 跨会话有效 |
| 3 | **先 kill 后代再 kill 本体** | 本体死后后代被 reparent，`pgrep -P` 就找不到它们了 |
| 4 | **心跳携带 pid** | 只有结束时记 pid，宿主中途崩溃就丢了这个信息 |
| 5 | **只清理「不是本进程」的 pid** | 本进程启动的子进程是活的，不该杀 |
